# 教师使用说明

本套件面向有 C 基础、未必学过汇编的软件工程本科生。基础成绩每实验满分 100，扩展任务单列，不能因为不做扩展而把基础满分降低。原材料与修订依据见[对应说明](source-mapping.md)。

## 课前准备与发放

1. 在目标 WSL2 Ubuntu 24.04 x86_64 环境按[安装指南](setup-wsl2.md)安装 apt 依赖。用普通用户执行 `make doctor`、`make prepare`。
2. 执行 `make check IMPL=reference`，保留完整输出。另按内核实验指导验证真实 QEMU 启动、用户程序部署和日志导出；自动检查不能替代未覆盖的交互场景。
3. 检查固定源码版本、兼容补丁、外部资产来源、许可证及 SHA-256。离线发放时准备匹配的 `.cache` 资产及依赖安装条件，不用任意旧镜像替换。
4. 执行 `make student-dist`，使用命令实际报告的发布路径。解包检查学生包没有参考答案、参考补丁或参考构建产物；再在干净目录检查文档入口、学生骨架构建和未实现提示。
5. 分发学生包与可用的环境说明。记录课堂实测的操作系统、工具版本、通过范围和已知限制，不能将参考实现预期行为标为课堂验证结果。

学生包不含参考实现，因而无需也不应要求学生运行 `IMPL=reference` 检查。完整教师仓库保留参考代码，用于课后讲评和验收。不要依赖目录隐藏来保密，应实际核对发布包内容。

## 教学安排

可采用“四、七、六、八、二、一、三、五”的顺序，不规定统一课时。算法实验先手算一轮再编码；并发实验观察多次运行；内核实验强调调用路径、部署及真实来宾证据。各内核实验工作区独立，保持干净基线，组合实验三和五作为扩展。

实验五的 AI 开发过程是必做要求。先要求学生提交调用约定与栈图，再生成汇编、修订、运行，最后讲评参考实现。提供参考汇编降低语法门槛，但不以照抄代码替代学生的生成、理解和调试过程。没有修订需求时允许提交检查依据，不要求人为制造失败。

## 验收原则

- 区分学生骨架预期的未实现失败与环境损坏；不把“能编译”当成功能完成。
- 验收学生实现时显式确认 `IMPL=student`，参考实现结果只用作基准。
- 用正常、边界和失败路径考查理解。银行家拒绝后检查真实状态未变化；文件系统通过实际操作验证权限，而非仅查看权限标签。
- 并发实验验证有序、无重复、无遗漏及容量限制；一次正确输出不足以证明不存在竞争。
- 内核必须在真实修改后的 0.11 中运行，不接受宿主机模拟输出、示例日志或单纯 QEMU 进程存活作为通过证据。
- 统计需给出单位、样本与区间；不完整轨迹单列。时间片对比使用相同工作负载，不要求得出“越小一定越好”等预设结论。

## 保护学生成果

`build/labNN/IMPL/kernel` 可能存有直接编辑的内核代码，磁盘副本可能保存程序与日志。重建工作区前保存差异和源码，关闭 QEMU 后再备份磁盘。构建保留工作区改动；任务源文件和工作区文件同时变更时会停止并要求合并。不要把删除整个 `build`、`.cache` 作为课堂统一修复指令。
