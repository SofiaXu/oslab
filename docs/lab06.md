# 实验六：作业调度——有空闲资源就一定能装入吗？

> 完整仓库包含独立参考实现；学生发布包不含 `reference/`。学生包中跳过参考演示，完成代码后使用默认的 `make check-lab6` 验收自己的实现。

## 概念与手算

**作业准入**决定哪些后备作业可以占用内存和设备；**CPU 调度**决定驻留作业中谁使用处理器。两者不能混为一谈。本实验所有作业在时间 0 已到达，输入行顺序就是到达顺序。

资源总量固定：100K 连续内存、5 台磁带机、最多两道驻留作业。内存采用**首次适应**：按地址递增查找第一个足够大的空闲段，不移动已经装入的作业；释放时相邻空闲区合并。磁带在准入时一次性分配，完成时归还。

手算：A 占 `[0,30)`，B 占 `[30,70)`。A 完成后空闲段为 `[0,30)` 和 `[70,100)`，总空闲为 60K，但 50K 的 C 无法装入。后面的 20K 作业 D 可以装入 `[0,20)`。这就是**外部碎片**和“跳过当前不可行作业继续查找”。

FCFS 从当前可行作业中选择最早到达者；SJF 从当前可行作业中选择运行时间最短者，同运行时间按输入顺序。不可先选一个不可行作业就停止，也不可只检查空闲总量。

## 明确 CPU 与时间模型

- **auto**：单 CPU、非抢占、按准入先后执行。开始和每次完成后，尝试填满驻留名额，再选最早准入的驻留作业独占 CPU。逻辑时钟一次增加它的完整运行时间；等待 CPU 的驻留作业不消耗自身运行时间。
- **manual**：只模拟资源与状态，不模拟 CPU 时间流逝，所以 `time` 固定为 0。由你指定哪一个驻留作业完成。完成后必须再输入 `ADMIT` 才尝试新的准入。

auto 不会调用 sleep，也不把两道作业当成两个 CPU 并行运行。手动模式用于观察资源变化；自动模式用于可重复比较准入策略。

## 文件与命令约定

启动：`lab06 fcfs|sjf auto|manual 作业文件`。

文件每行一条，无注释，五列以空白分隔：

```text
用户名 作业名 运行时间(整数分钟) 内存(K) 磁带台数
A ZYA 18 15 2
B ZYB 30 60 1
C ZYC 6 50 3
D ZYD 24 10 2
E ZYE 6 30 3
```

以上保留原题五个作业，将 0.3、0.5、0.1、0.4、0.1 小时统一换成 18、30、6、24、6 分钟，避免浮点比较。最多 128 个作业；运行时间 1～1000000；内存 1～100；磁带 0～5；用户名和作业名各最多 31 字节、不能含空白；二者组合不能重复。资源需求超过系统总量直接报错，不让自动模式永久等待。

手动命令每行一条：

| 命令 | 操作 |
|---|---|
| `ADMIT` | 反复按策略装入，直到两道驻留或没有可行作业 |
| `COMPLETE 用户名 作业名` | 仅允许完成当前驻留作业，释放资源 |
| `SHOW` | 打印所有作业及空闲分区 |
| `QUIT` | 退出，EOF 同样有效 |

`WAIT/RESIDENT/DONE` 对应收容/驻留执行/完成。`ADMIT`、`COMPLETE` 为事件；`STATE` 显示驻留数和剩余磁带；`HOLE start=... size=...` 为按地址排序的最大连续空闲段；已完成作业的 start 保留历史地址，不代表继续占用。

成功退出 0；手动模式出现拒绝命令最终退出 1，但继续接受后续命令；格式、文件、数值错误退出 2。

## 分步任务

1. 读入作业表并打印；校验状态初值、资源范围与重复键。
2. 完成 `first_fit`。可用 100 个格子记录每 K 的归属，或维护显式空闲分区链表；无论哪种表示，必须得到相同的首次适应结果。
3. 实现 FCFS/SJF 的可行候选选择，并记录准入顺序。
4. 完成释放操作，检查内存、磁带和驻留数全部归还。
5. 先实现手动模式，再加入确定性的单 CPU 自动事件循环。
6. 对两种策略输出每次准入后的作业表，比较准入顺序而非只比较最终时间。

## 运行与预期

```bash
make lab6 IMPL=reference
./build/lab06/reference/lab06 fcfs auto labs/lab06/fixtures/original.txt
./build/lab06/reference/lab06 sjf auto labs/lab06/fixtures/original.txt
./build/lab06/reference/lab06 fcfs manual labs/lab06/fixtures/fragmentation.txt < labs/lab06/fixtures/manual.txt
python3 tests/test_algorithms.py
make lab6 IMPL=student
```

原题 FCFS 准入顺序：ZYA、ZYB、ZYD、ZYC、ZYE；SJF：ZYC、ZYA、ZYE、ZYD、ZYB。两者最后均为 `time=84 resident=0 tapes_free=5`，且空闲段为 `start=0 size=100`。总 CPU 需求相同，最终总时间相同并不意味着顺序相同。

碎片例子的准入顺序是 A、B、D、C。A 完成后 C 被跳过，D 从地址 0 装入。D、B 完成后空闲区合并，C 才从地址 0 装入。该命令文件停在 C 驻留状态，故不会出现 `ALL_DONE`。

测试脚本默认构建参考程序，覆盖资源、碎片、顺序和拒绝行为。使用下方环境变量可让同一套测试验收学生实现，还应补充自己的测试数据。

## 自检、常见问题

- 始终满足：驻留数≤2；已用磁带+剩余磁带=5；被占内存+空闲内存=100；每个驻留作业的内存连续且不重叠。
- 没有足够大的连续段时，能否跳过候选并继续查找？不能为“通过测试”移动 B。
- 重复完成、完成后备作业、错误用户名应拒绝，资源不得再增加。
- auto 若无法推进，应报明确错误，不要无限循环；manual EOF 可以在作业未完成时退出。
- 原参考代码存在把磁带数量从内存扣除、边界比较和链表等错误，不要逐行照抄。
