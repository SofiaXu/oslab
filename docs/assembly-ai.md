# 实验五：用 AI 辅助开发汇编

实验五要求你实际使用 AI 生成并调试自己的栈切换汇编。目标是把 C 代码中的 PCB、`fork`、调度逻辑与汇编保存的现场对应起来。无需从空白背写汇编，但必须能解释最终代码。完整参考实现可以在完成初次实现与测试后查阅，报告说明查阅时间及借鉴内容。

## 先画图，再请求代码

阅读实验五指导和当前内核调用点，整理下面四项，填写真实值而非猜测：

1. `switch_to` 的入口在哪里？参数放在寄存器还是栈上？调用者要求哪些寄存器保持不变？
2. 当前 PCB、目标 PCB、保存的内核栈指针字段在哪里？字段偏移如何由当前结构体和构建配置确认？
3. 切换前后栈顶各是什么？正常返回与子进程第一次调度的返回路径有什么不同？
4. 切换中需要怎样更新 LDT、TSS 的内核入口栈及 `fs`？哪些值来自现有实验内核的约定？

用表格或图画出每次 `push`、`pop`、`call`、`ret` 前后的栈顶。x86 的栈向低地址增长；切换 `%esp` 会让后续出栈和返回使用另一块内存。通用示意如下，**不是可以直接照搬的实验栈布局**：

```text
高地址
    调用者已有的数据
    返回地址          ← ret 最终要取到的地址
    保存的寄存器      ← 顺序必须与恢复顺序配对
低地址                ← 当前 esp，实际位置随指令变化
```

AT&T 语法通常写“源操作数，目的操作数”，寄存器带 `%`，立即数带 `$`。本实验是 32 位 x86；不要混用 `%rsp`、64 位调用约定或网上任意版本的 PCB 偏移。

## 可直接改写的提示词

把以下模板中的占位内容替换为你正在修改的真实代码片段和自己画的图。不要要求 AI 无上下文生成整套内核。

```text
我在固定版本 Linux 0.11 教学内核中，将硬件任务切换改为内核栈切换。
目标架构：32 位 x86；汇编语法和符号规则：[从当前源码填写]。
构建命令：make lab5。学生实现自检：make check-lab5。
调用点及参数传递：[贴真实代码]。
PCB 新字段与偏移依据：[贴结构体及确认方法]。
必须保存的寄存器、段状态及返回约定：[填写]。
我画出的普通进程和首次运行子进程栈布局：[填写]。
请先检查接口和栈布局是否一致，再生成最小 switch_to 汇编。
逐条说明指令目的、esp 如何变化，以及与 fork 构造子栈的对应关系。
有上下文缺失请指出，不能虚构偏移、测试输出或启动成功结论。
```

首次生成后先人工检查，再构建。出现错误时补充实际报错、调用点、反汇编或寄存器观察：

```text
这是本轮补丁、第一条构建错误/实际运行现象，以及我的栈布局推演：[…]
请指出可验证的原因并给出最小修改，说明修改会影响哪些寄存器和返回路径。
不要一次重写无关模块，不要声称已经运行过我的环境。
```

## 分阶段核对

| 阶段 | 你要检查的内容 | 保存什么证据 |
| --- | --- | --- |
| 接口 | 汇编入口与 C 调用一致，字段偏移有来源 | 调用约定表、结构体变化 |
| 汇编与链接 | 指令位宽、符号和恢复顺序匹配 | 构建日志、关键反汇编 |
| 子进程首次运行 | 人工构造的栈与恢复逻辑一致，fork 返回值符合父子语义 | 子栈图、代码解释 |
| 启动与使用 | 修改后的真实内核启动，shell 可用 | 来宾启动和交互记录 |
| 重复切换 | 多次创建、等待、退出进程仍正常 | 测试输入、PID/退出记录、自检输出 |

`make lab5` 与 `make check-lab5` 通过只是证据的一部分，还要根据实验五指导验证真实来宾。黑屏时先排查显示后端，再检查内核异常；不能仅靠 QEMU 进程仍在运行宣布切换正确。没有实际完成的验证，明确写“未验证”。

## 必须能独立回答

- 为什么只改变 `%esp` 还不足以完成正确的进程切换？
- 为什么子进程第一次被调度需要特殊构造内核栈？fork 返回 0 的路径在哪里形成？
- 原实验中的 `+4096`、`ESP0`、`ss0` 分别对应什么？这些约定在你使用的代码中如何成立？
- `ebp`、`ebx`、`ecx` 从哪条路径传入子栈，出栈后在哪里使用？
- 为什么切换 LDT 后要重新装载 `fs`，先装载再换 LDT 会有什么问题？
- 去掉硬件任务切换是否等于可以删除 TSS 的所有用途？

答案应结合自己的最终代码和栈图；不能只粘贴 AI 的文字。
