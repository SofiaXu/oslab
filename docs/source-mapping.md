## 不再照搬的错误与歧义

### 实验二：分值与同步要求

原文同时写“选做，占 10 分”“不做满分 80 分”，而列出的程序、信号量与报告比例相加也无法支持这个说法。新版将 Ubuntu 基础任务按 100 分评价，0.11 信号量扩展单列，不因未做扩展降低基础满分。

原文要求消费者的 PID 顺序可以变化，但数字应从 0 递增。只在缓冲区取数时加锁、解锁后再打印不能保证这一点。新版把输出顺序纳入同步设计。Ubuntu POSIX 命名信号量接口与 0.11 教学扩展接口也须区分，不能直接复制函数原型。

### 实验三：日志采集边界

原题要求内核直接维护启动至关机的磁盘日志。新版改为内核从启动开始记录真实事件，来宾测量程序在运行期间把事件导出为 `/var/process.log`，避免调度器中的文件写入再次阻塞和调度。队列容量 8192 条，溢出即判测量无效；收集程序退出后不继续写盘。因此保留了真实内核状态跟踪与时间片比较目标，但不声称实现了原题的全程磁盘日志。完整接口和边界见[实验三](lab03.md)。

### 实验四：维度与安全判定

原文算法说明一处使用 `available[i][j]`，但可用资源是按资源种类索引的一维数组。安全检查必须判断所有进程能否依次假想完成，不能仅凭最后一次循环的标志值宣布安全。不安全请求必须恢复试探前状态。原参考代码混用 C/C++ 类型书写，不作为可直接编译的学生骨架。

### 实验六：资源与内存模型

原示例在选中作业后出现用磁带申请量扣减内存的代码，并未正确落实全部资源更新；仅有一个“剩余内存总量”也不能表示不可移动的连续分区。新版分别维护内存块、磁带数量与驻留数，允许资源恰好满足，释放时合并相邻空闲区。

FCFS/SJF 选择的是可准入作业，不自动说明 CPU 如何调度。手动完成与自动事件模式分别说明完成规则，不把随机输入当成可复现的算法比较。原文关于“处理器调度参见实验二”的指引也不作为本套件的实验依赖。

### 实验七：算法和指标

统一使用 FIFO（先进先出）、LRU（最近最久未使用）、LFU（最不经常使用）。LFU 采用本次驻留期间的访问计数，同频按进入内存先后淘汰，避免不同清零和平局规则导致答案不可比。

缺页次数包含填充空页框的情况；实际置换只统计已有页面被淘汰。缺页率与置换率均除以总引用次数。原文“缺页调度次数”等含混说法在新版中以这两个独立计数表达。原 Windows/C++ 示例中的 `conio.h`、`WM_TIMER` 等不作为 Ubuntu 依赖。

### 实验八：多文件与安全边界

原文“每用户最多保存一个文件”与后续多文件输入、同时打开 K 个文件的设计不一致。新版明确每用户可有多个文件，保存容量与同时打开上限是不同约束。重写不可编译的结构体、字符串比较和链表操作示例；用户名只是教学身份，EXEC 只验证模拟执行权限，不启动宿主文件。

## 思考题与实验边界

保留实验一的参数传递与新增调用步骤、实验二的去信号量对照及同步方案分析、实验三的并发体验及时间片比较、实验五的 4096/ESP0/ss0、fork 子栈和 LDT/fs 等问题。原文含图片的代码题需以实验指导中完整呈现的片段为准，不从缺失的文字抽取结果猜代码。

原实验五关于切换周期数和性能的叙述不作为现代机器或 QEMU 的通用结论；本实验首先验证语义正确，再在明确负载和测量条件下讨论表现。真实内核实验与宿主算法模拟分开验收，不以模拟程序替代内核修改。
