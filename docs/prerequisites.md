# 开始前应掌握什么

你不需要先写过操作系统，也不需要先掌握完整的 x86 汇编。需要能读懂 C 函数、数组、结构体和指针，并愿意用小输入逐步验证程序。

## C 语言自检

开始前，确认自己能解释以下问题；不熟悉时先写十几行的小程序练习。

- 数组下标为何必须小于长度？字符串末尾的 `\0` 占几个字节？
- `sizeof(pointer)` 为什么不是动态数组的长度？
- `malloc` 失败返回什么？哪个函数负责释放内存？
- 为什么字符串内容比较用 `strcmp`，不能用指针的 `==`？
- `fread`、`fwrite`、`read`、`write` 的返回值分别说明什么？
- 整数除法为什么会让 `1 / 3` 得到 0？怎样计算百分比？

优先看第一个编译错误，并保留警告。不要用类型强制转换或删除检查来掩盖问题。下面的小练习在 Ubuntu 临时目录完成：

```bash
mkdir -p ~/oslab-practice
cd ~/oslab-practice
cat > hello.c <<'C'
#include <stdio.h>
int main(void) {
    puts("hello, oslab");
    return 0;
}
C
gcc -std=c11 -Wall -Wextra hello.c -o hello
./hello
```

预期输出只有 `hello, oslab`。套件实验使用根目录 Make 入口，不用这个命令替代内核构建。

## 命令行与进程

| 概念 | 在实验中怎么用 |
| --- | --- |
| 当前目录、相对路径 | `make` 在仓库根目录运行；来宾路径属于另一套文件系统 |
| 标准输入/输出、重定向 | 保留输入数据和文本输出，便于复现 |
| 退出状态 | `echo $?` 查看上一条命令的状态；非零表示需检查原因 |
| 进程与 PID | `fork` 产生子进程，父进程 `wait` 等待回收 |
| 并发与共享 | 多进程拥有独立地址空间；普通全局变量不能自动实现进程间共享 |
| 阻塞 | 等待资源时暂时不能运行；不是一直占用 CPU 的循环 |

`fork()` 在父进程返回子 PID，在子进程返回 0，失败时返回 -1。父进程应检查失败并回收已创建的子进程。文件共享状态也需同步：共享文件不代表读、修改、写回三步自动成为原子操作。

生产者消费者中，可先把 `empty=10`、`full=0`、`mutex=1` 手算一轮。把取数保护好却在解锁后输出，仍可能使打印数字乱序。不要依赖“我运行一次刚好没出错”证明同步正确。

## 算法实验的手算准备

- **银行家算法**：理解 `Need = Max - Allocation`。安全检查中的 `Work` 是工作副本；检查过程假想的进程结束，不应直接释放真实已分配资源。不安全也不等于已经发生死锁。
- **作业调度**：区分“允许进入内存”与“占用 CPU”。总空闲内存足够，不一定存在足够大的连续空闲区；完成作业后需要释放并合并相邻空闲块。
- **页面置换**：有空页框时调入新页会缺页，但不发生淘汰。引用 `1,2,1,3`、两个页框时，FIFO 和 LRU 在最后一步的淘汰选择不同。
- **文件系统**：目录负责按名查找，打开表负责记录正在使用的文件；读、写、执行权限是三个不同能力。这里的“执行”是模拟权限判断，不执行宿主程序。

## 读内核所需的最少知识

用户态程序不能直接把用户指针当作内核内存随意访问；系统调用是进入内核的受控入口。PCB 保存进程管理信息，内核栈保存进程在内核中的调用现场，LDT 与段寄存器影响地址解释。

实验三的 tick 是来宾内核时钟单位，不是宿主机秒表。对完整轨迹应区分运行时间、就绪等待时间、阻塞时间及从创建到退出的周转时间。缺少创建或退出事件的轨迹不能悄悄算成完整样本。

实验五先学习[汇编与 AI 指南](assembly-ai.md)，再按实验指导核对真实调用约定、PCB 偏移和栈布局。不凭空猜测偏移，不把现代 64 位汇编直接放进 32 位旧内核。

## 工作习惯

每完成一个小任务就记录输入、输出和解释；修改内核前先备份学生源码及含有成果的工作区。只运行自己理解用途的命令，尤其不要把删除整个 `build` 当成通用修复手段。提交前用[报告模板](report-template.md)检查是否有足够证据让别人重现你的结论。
