# 故障排查

先确认“在哪个环境、执行哪条命令、第一处错误是什么”。优先保存完整文本输出；截图用于辅助定位窗口与来宾状态。`make` 的最后一行常只是汇总，真正原因通常在前面。

## 安装与工具链

| 现象 | 检查与处理 |
| --- | --- |
| PowerShell 不认识 `make`，Ubuntu 不认识 `wsl` | 命令环境混淆；安装 WSL 在 PowerShell，实验构建在 Ubuntu |
| `make` 报没有目标或没有 Makefile | 用 `pwd`、`ls -a` 确认在仓库根目录，且学生包完整解压 |
| WSL 安装报虚拟化错误 | 在 PowerShell 查看 `wsl --list --verbose`；确认 Windows 功能和 BIOS/UEFI 虚拟化，按官方安装排错说明处理 |
| `apt` 找不到包 | 执行 `sudo apt update`，检查 `/etc/os-release`、`dpkg --print-architecture` 及软件源；需要时由教师确认 Ubuntu 官方仓库配置 |
| 缺少 `make`、GCC、QEMU、Python | 按[安装指南](setup-wsl2.md)安装依赖，再执行 `make doctor` |
| 32 位编译缺少头文件或库 | 检查是否在 amd64 Ubuntu 安装 `gcc-multilib`，不要改系统 GCC 链接 |
| 构建目录权限拒绝 | 查看目录所有者；不要继续用 `sudo make`，先确认是否曾以 root 解压或构建，修复自己项目内的权限 |
| `/bin/bash^M` 或脚本格式错误 | 文件可能变为 CRLF；在编辑器中把受影响的文本保存为 LF，不要批量改写二进制资产 |

不要看到旧内核编译错误就安装失效 PPA。先保留第一条报错、编译器版本和当前补丁差异；确认使用的是套件固定版本及兼容修改。

## 下载与准备

`make prepare` 失败时，区分 DNS/代理/连接错误、解压错误与 SHA-256 不匹配。网络恢复后重新运行准备入口；不要跳过校验或用名称相近的镜像凑数。离线时向教师索取对应版本缓存及来源/校验记录。

缓存目录为 `.cache`，但学生工作区在 `build/labNN/IMPL/kernel`，程序与日志也可能位于磁盘副本中。**不要通过删除整个 `build` 来修复下载问题。** 若需处理损坏缓存，只处理错误信息明确指向的资产，并先保留诊断信息。

## QEMU 没有窗口或窗口黑屏

1. 在 Ubuntu 查看 `printf '%s\n' "$DISPLAY" "$WAYLAND_DISPLAY"` 和 `qemu-system-i386 -display help`。环境变量存在只能说明配置线索，不保证窗口实际可用。
2. 在 PowerShell 执行 `wsl --list --verbose`，确认 Ubuntu 为 WSL2；保存工作后按安装指南更新 WSL 并重启 WSL。
3. 检查是否在 SSH/无图形会话内运行，或手动 `DISPLAY` 设置覆盖 WSLg。图形问题与来宾内核异常分开调查。
4. 需要纯终端时使用运行器支持的 VGA curses 模式，具体入口按内核实验指导；QEMU 后端为 `-display curses`。不要凭空重组镜像、根设备或硬盘几何参数。

`-nographic` 常把串口与监视器接到终端，并不保证显示 VGA 控制台；原版 Linux 0.11 不保证支持串口控制台。因此“终端没文字”不能直接判定内核没有启动。curses 也只适合文本显示，不保证呈现启动过程的所有模式。

若窗口能显示但修改内核后重启、死机，核对使用的工作区和磁盘，保存日志并回看最近一次内核修改。实验五优先检查调用约定、PCB 偏移、恢复顺序、子进程初始栈以及 LDT/fs；不要用参考镜像启动成功证明学生内核正确。

## 来宾程序与日志

| 现象 | 检查与处理 |
| --- | --- |
| Ubuntu 程序在 0.11 无法执行 | 旧来宾的 ABI/可执行格式不同；使用内核实验提供的用户程序编译和部署流程 |
| 新增调用似乎没有生效 | 确认构建的是学生实现、启动的是当前实验镜像、用户程序的调用号与内核表一致 |
| Ubuntu 找不到 `/var/process.log` | 该路径属于来宾；按实验三指导导出，再在宿主分析 |
| 日志缺事件或时间异常 | 确认运行后已完成相应写出/导出，检查 PID 和 tick；不完整轨迹单列，勿编造退出事件 |
| 交换文件时提示磁盘占用 | 停止对该镜像的并行访问；不要在 QEMU 运行时挂载或修改同一磁盘文件 |

修改来宾文件、关闭来宾和导出数据遵循该实验工具流程。宿主文件、缓存镜像、实验磁盘副本是不同对象，复制前确认源和目的。

## 运行成功却检查失败

- **学生骨架未完成**：检查未实现提示和待完成函数。能编译、显示菜单不等于算法正确。
- **实现选择错误**：默认 `IMPL=student`；`make check-lab4 IMPL=reference` 检查的是参考实现。学生包不含参考答案，参考入口不可用不表示学生代码损坏。
- **生产者消费者**：检查输出是否落在正确临界区，是否丢失/重复、是否越界，结束标记与清理是否覆盖所有子进程。偶发正确不能证明同步无误。
- **银行家算法**：检查被拒绝的请求有无污染状态；安全检查应操作工作副本。
- **作业调度**：检查连续空闲块而非仅剩余总量；区分准入与完成顺序。
- **页面置换**：确认序列、页框数和 LFU 平局规则相同，缺页与实际置换分开计数；用保存的序列重放比较。
- **文件系统**：检查当前教学用户、文件权限、打开上限 K 和重复/不存在对象的处理；这不是宿主文件权限测试。

程序卡住先保存输入和最后输出，再中断当前任务。不要为了“清理”杀死其他同学或其他项目的进程，也不要批量删除所有命名信号量；只清理当前实验创建的资源。

## 重建前先保护成果

确认哪些是学生源码、哪些是实验工作区。保存源码副本或本地差异；备份含日志的磁盘前先关闭对应 QEMU。重新准备资产与重新创建工作区不是同一操作，前者不应擦除后者的学生修改。未确定工具行为时先查实验指导，不盲用强制覆盖或递归删除。

## 求助时提供这些信息

在 Ubuntu 仓库根目录收集以下内容，并附实际执行命令、完整错误输出和最近修改摘要：

```bash
pwd
cat /etc/os-release
uname -m
gcc --version
make --version
qemu-system-i386 --version
python3 --version
make doctor
```

WSL 问题另附 PowerShell 的 `wsl --list --verbose`；内核问题附实验编号、`IMPL`、实际工作区、启动方式和来宾画面。分享前去掉密钥、账号及无关路径信息。不要只说“运行不了”，也不要把 AI 的推测当作实测结论。
