# 操作系统实验套件

面向有 C 语言基础的软件工程本科生。本套件把八个实验组织为“阅读概念 → 完成 C 骨架 → 运行与自检 → 解释结果”的学习过程。内核实验使用真正的 Linux 0.11；算法实验在 Ubuntu 终端运行。实验五必须使用 AI 辅助生成并调试汇编，不要求先修完整的汇编课程，但必须理解自己提交的代码。

## 从这里开始

1. 按 [WSL2 安装指南](docs/setup-wsl2.md)准备 **WSL2 + Ubuntu 24.04 x86_64 + WSLg**。原生 Ubuntu 24.04 x86_64 可从安装依赖开始。
2. 阅读 [前置知识](docs/prerequisites.md)，确认自己能编译 C 程序、理解指针并操作文件。
3. 在 Ubuntu 中进入仓库根目录，检查环境、准备资产，再开始一个实验。

```bash
make doctor
make prepare
make lab4
make run-lab4
make check-lab4
```

`lab4` 是示例；其他实验用 `lab1` 到 `lab8`。构建成功只表示程序可以生成，不代表任务完成。学生骨架中的未实现提示或相应检查失败，需要按指导补全；编译器缺失、下载失败等环境问题则应先解决。

## 八个实验

| 编号 | 主题 | 运行位置 | 要掌握的能力 |
| --- | --- | --- | --- |
| 一 | 系统调用 `iam`、`whoami` | Linux 0.11 来宾 | 理解用户态到内核态的调用路径与参数交换 |
| 二 | 生产者与消费者 | Ubuntu；0.11 信号量为扩展 | 用文件共享容量为 10 的缓冲区，用信号量保证同步和输出顺序 |
| 三 | 进程轨迹与调度统计 | Linux 0.11 来宾；宿主分析日志 | 跟踪 N/J/R/W/E 状态，比较时间片与统计指标 |
| 四 | 银行家算法 | Ubuntu | 检查安全序列，试探分配并在失败时完整回滚 |
| 五 | 基于内核栈的进程切换 | Linux 0.11 来宾 | AI 辅助编写汇编，配合 PCB、fork 和调度代码验证栈切换 |
| 六 | 作业调度模拟 | Ubuntu | 在连续内存、磁带机与驻留数限制下比较 FCFS/SJF 准入 |
| 七 | 页面置换模拟 | Ubuntu | 实现 FIFO/LRU/LFU，逐步观察并保存、重放引用序列 |
| 八 | 二级目录文件系统模拟 | Ubuntu | 实现多用户、多文件、打开上限和访问权限检查 |

实验编号保留原材料顺序。初学者可按 **四 → 七 → 六 → 八 → 二 → 一 → 三 → 五** 学习，先练习可手算的模拟程序，再进入并发和真实内核。内核实验分别从干净基线开始，实验五不依赖实验三的修改；组合日志比较属于扩展。

## 命令约定

所有 `make` 命令都在 **Ubuntu 的仓库根目录**运行，不加 `sudo`。

| 命令 | 用途 |
| --- | --- |
| `make doctor` | 检查环境，定位缺失依赖 |
| `make prepare` | 准备实验需要的固定版本外部资产 |
| `make labN` | 构建第 N 个实验，N 为 1 到 8 |
| `make run-labN` | 运行第 N 个实验 |
| `make check-labN` | 检查第 N 个实验 |
| `make check IMPL=reference` | 检查整套参考实现，供教师或完成任务后核对 |
| `make student-dist` | 生成不含参考答案及其构建产物的学生发布包 |

默认 `IMPL=student`。需要核对时显式使用，例如 `make check-lab4 IMPL=reference`；运行参考实现可用 `make run-lab4 IMPL=reference`。参考实现通过不代表学生实现通过，报告须写明实际选择。核心 C 任务保留在学生骨架中，参考实现独立；学生发布包不提供参考答案。

## 实验文件与运行边界

- Linux 0.11 以 [yuan-xy/Linux-0.11](https://github.com/yuan-xy/Linux-0.11) 为移植基础，使用仓库集成的固定版本源码和现代 GCC 兼容修改；不要临时替换为上游最新代码，也不要照旧教程替换系统默认编译器。
- 各内核实验按实现隔离，工作区位于 `build/labNN/IMPL/kernel`，如实验一学生版为 `build/lab01/student/kernel`。优先修改 `labs/labNN/student/kernel/` 中的任务文件；完整内核集成也可修改工作区，修改前确认文件位置。
- 重新构建会保留工作区源码和来宾磁盘。任务文件的新版会同步到未修改的工作区文件；两处同时修改会报冲突，要求手动合并，不会静默覆盖。提交时同时保存自己的任务源码及工作区改动。
- `.cache` 存放缓存资产；内核实验使用各自的磁盘副本。缓存不是作业备份。工作区和来宾磁盘可能包含你的成果，勿直接删除 `build` 或在 QEMU 运行时操作磁盘。
- QEMU 使用 TCG 软件模拟，不要求 WSL 嵌套虚拟化。默认图形窗口通过 WSLg 显示；终端模式应使用 VGA 的 curses 显示，不能假定原版 0.11 支持串口控制台。
- 来宾编译、部署程序和导出日志按对应内核实验指导操作。Ubuntu 编译出的普通可执行文件不能直接作为 Linux 0.11 程序使用。

## 提交与求助

使用 [Markdown 报告模板](docs/report-template.md)，提交学生源码、复现实验的输入、原始日志、结果分析及必要截图。实验五另附 AI 提示词、修改记录、指令解释和运行证据，详见 [汇编与 AI 指南](docs/assembly-ai.md)。每个实验基础成绩满分 100，扩展另列。

遇到问题先看 [故障排查](docs/troubleshooting.md)。教师可阅读 [教师说明](docs/teacher.md)、[原材料对应与修订](docs/source-mapping.md)和[实测记录](docs/validation.md)。第三方来源与许可边界见 [THIRD_PARTY.md](THIRD_PARTY.md)。示例输出和参考结果用于理解，不得当作自己运行的证据。
